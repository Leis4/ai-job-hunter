# Qwen Engine: локальная и облачная генерация

Единый движок `core/qwen_engine.py` обслуживает оба провайдера. Письма, анализ
требований, ответы на вопросы и классификация используют один промпт, один пакет
подтверждённых фактов и один валидатор.

## Провайдеры

| Режим | Что делает |
| --- | --- |
| `auto` (по умолчанию) | простые письма — локально; сложные и приоритетные — AITUNNEL; при ошибке одного провайдера используется второй |
| `local_only` | только Ollama `qwen3.5:4b`, без оплаты |
| `cloud_only` | только Qwen через AITUNNEL |

Локальная модель не держится в VRAM: `keep_alive` по умолчанию `30s`, после
простоя Ollama сама выгружает модель. Одновременные локальные генерации
ограничены одним потоком.

## Модели AITUNNEL

ID проверены по публичному каталогу `https://api.aitunnel.ru/public/aitunnel/models`
20.11.2026:

- `qwen3.7-flash` — 6 / 26 ₽ за 1M входных/выходных токенов, контекст 1M;
  используется для массовых писем.
- `qwen3.8-flash` — 30 / 94 ₽, контекст 1M, качественнее; используется для
  сложных и приоритетных вакансий.

Обе модели можно заменить в `config/settings.json` →
`qwen.cloud.models.cheap|quality` или в интерфейсе «Настройки → AI и бюджет».

## Ключ AITUNNEL

Ключ читается в таком порядке:

1. переменная окружения `AITUNNEL_API_KEY` (или `key_env` из настроек);
2. файл `data/aitunnel_api_key.bin`, зашифрованный Windows DPAPI.

Ключ никогда не пишется в SQLite, Git, логи, письма или frontend. Сохранить его:

```powershell
py -3 jobhunter.py secret aitunnel set
```

Команда запросит ключ скрытым вводом. В интерфейсе ключ можно сохранить в
«Настройки → AI и бюджет → Ключ AITUNNEL» (поле пароля, запись в DPAPI).

## Бюджет

Используется существующий ledger `ai_spend`; второй счётчик не создаётся.
Лимиты:

- месячный бюджет — `llm.aitunnel.monthly_budget_rub` (иначе пересчёт из USD);
- максимум за письмо — `qwen.cloud.max_letter_rub` (по умолчанию 1.5 ₽);
- максимум за сутки — `qwen.cloud.max_daily_rub` (по умолчанию 30 ₽);
- облачный fallback — `qwen.cloud.allow_fallback`;
- приватность — `privacy.allow_cloud_llm` (по умолчанию включена; контакты в
  облако не передаются).

При превышении лимита платный вызов не выполняется, используется локальная Qwen.
Если недоступны оба провайдера, письмо сохраняется как локальный фактологический
черновик с пометкой для ручной проверки; отправка такого письма автопилотом не
происходит.

## Проверки

```powershell
py -3 tests/qwen_engine_smoke.py   # маршрутизация, fallback, бюджет, кэш, приватность
py -3 tests/qwen_letter_live.py    # реальная локальная генерация на временной БД
py -3 jobhunter.py qwen status
py -3 jobhunter.py qwen test
```

`qwen test` и кнопка «Проверить генерацию» создают тестовое письмо, но ничего не
отправляют.
